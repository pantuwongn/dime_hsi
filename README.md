# แผนเทรดรายวัน — DW HSI / DW SET50 / หุ้นไทยเดย์เทรด / หุ้นสวิง / DR

เครื่องมือบรรทัดเดียวสำหรับพอร์ตเล็ก: รันตอนเช้า อ่านผล วาง order แล้วไปทำงาน

```bash
python3 run.py                 # ทุกก้อนที่มีงบใน ALLOC
python3 run.py --bucket dw     # เฉพาะ DW ฮั่งเส็ง
python3 run.py --bucket s50    # เฉพาะ DW SET50
python3 run.py --bucket cheap  # เฉพาะหุ้นไทย < 3 บาท (สวิง)
python3 run.py --bucket day    # เฉพาะหุ้นไทยเดย์เทรด
python3 run.py --bucket dr     # เฉพาะ DR (ตอนนี้พักอยู่ — จะบอกให้รู้แทนที่จะสแกน)
python3 run.py --no-journal    # ไม่บันทึกลง journal.jsonl
python3 run.py --plain         # ปิดกรอบและแถบกราฟ (สำหรับ pipe ลงไฟล์)
python3 run.py --color | less -R   # บังคับใช้สีตอน pipe
python3 selftest.py            # ตรวจว่าทุกบรรทัดยังพอดีกรอบ (ต้องต่อเน็ต)
python3 test_offline.py        # ตรวจตรรกะเงิน ไม่ต้องต่อเน็ต
```

หลังกดซื้อ/ขายจริง บอกมันด้วย ไม่งั้นมันไม่รู้ว่าคุณถืออะไรอยู่

```bash
python3 run.py --took SIRI                        # ซื้อตามที่แนะนำเป๊ะ
python3 run.py --took SIRI --price 1.55 --lots 5  # ได้ราคา/จำนวนไม่ตรงที่แนะนำ
python3 run.py --close SIRI --price 1.60          # ขายหมด
python3 run.py --close SIRI --price 1.60 --lots 2 # ขายบางส่วน
python3 run.py --status                 # ดูโควตาวันนี้กับของที่ถืออยู่ ไม่ต้องสแกน
python3 run.py --review                 # ก้อนไหนทำเงินจริง ก้อนไหนควรตัดทิ้ง
python3 run.py --force                  # ดูตลาดทั้งที่ชนเบรกเกอร์แล้ว
```

ซื้อตัวที่สคริปต์ไม่ได้แนะนำก็บันทึกได้ แค่ต้องบอกให้ครบ

```bash
python3 run.py --took PTT --price 32.50 --lots 1 --sl 31.50 --tp 34.00 --bucket cheap
```

**คำแนะนำเป็นแค่ค่าตั้งต้น ไม่ใช่ตัวบันทึก** — ได้ของไม่ครบ ได้ราคาอื่น ซื้อน้อยลง
เพราะเปลี่ยนใจ หรือซื้อตัวที่มันไม่เคยพูดถึง ต้องเขียนลงได้หมด เพราะสมุดที่รับ
เฉพาะสิ่งที่ทำนายไว้ คือสมุดบันทึกคำทำนาย ไม่ใช่สมุดบันทึกการเทรด

ซื้อซ้ำตัวเดิมจะรวมเป็นก้อนเดียวคิดต้นทุนเฉลี่ยให้ และขายบางส่วนจะตัดเป็น lot จริง
— ขาย 2 จาก 5 lot แล้วอีก 3 lot ยังอยู่ในสมุด พร้อมความเสี่ยงที่ลดลงตามส่วน

**ไม่ต้องติดตั้งอะไรเลย** ใช้ Python standard library ล้วน — กราฟทั้งหมดวาดด้วย
ANSI + Unicode box drawing ไม่ได้พึ่ง `rich` หรือ lib ใด ๆ

## สีบอกอะไร

ดูแค่สีก็รู้ว่าต้องทำอะไร ไม่ต้องอ่านตัวเลข

| ป้าย | สี | หมายความว่า |
| :-- | :-- | :-- |
| `▲ ซื้อ CALL DW` | พื้น**เขียว** | สัญญาณขึ้น — ซื้อ Call DW ตัวที่ระบุ |
| `▼ ซื้อ PUT DW` | พื้น**แดง** | สัญญาณลง — ซื้อ Put DW ตัวที่ระบุ |
| `▲ ซื้อ` | พื้น**เขียว** | ก้อนหุ้น (B / C / E) มีตัวให้เข้า |
| `■ ไม่เข้า` | พื้น**เหลือง** | สัญญาณไม่ถึงเกณฑ์ → ถือเงินสด |
| `✕ ไม่มีของให้ซื้อ` | พื้น**เทา** | สัญญาณมา แต่ DW ทุกตัวติดเกณฑ์ spread/theta |

**กรอบทั้งกล่องเปลี่ยนสีตามคำตอบด้วย** — เขียวทั้งกล่อง = Call, แดงทั้งกล่อง = Put,
เหลือง = ไม่เข้า ในตาราง DW ชื่อ Call เป็นเขียว ชื่อ Put เป็นแดงเสมอ

ปิดสีทั้งหมดด้วย `NO_COLOR=1 python3 run.py`

**หมายเหตุเรื่อง sparkline** — ไม่มีแหล่งข้อมูลย้อนหลังฟรีที่เข้าถึงได้จากที่นี่
(Yahoo ตอบ 429, SET/settrade ติด Imperva, thaidw มีแต่รูปกราฟ) เส้นจึงสร้างจาก
`.cache/series.jsonl` ที่บันทึกทุกครั้งที่รัน ยิ่งรันบ่อยเส้นยิ่งยาว
ตอนยังไม่มีข้อมูลจะขึ้นเป็นจุด `····` ไม่ใช่เส้นที่เดาขึ้นมาเอง

## ก้อนที่ดูอยู่ — เปิดใช้ 4 จาก 5

| ก้อน | ดูอะไร | ถือนานแค่ไหน | งบ |
| :-- | :-- | :-- | --: |
| **A · DW HSI** | DW ฮั่งเส็งที่จดทะเบียนในไทย ผู้ออก **18 (KTX)** และ **28 (MACQ)** | เดย์เทรด ปิดก่อน 15:45 | 500฿ |
| **B · หุ้นไทยถูก** | หุ้น SET ราคาต่ำกว่า 3 บาท | สวิง 5 วัน | 1,000฿ |
| **C · DR** | DR ที่จดทะเบียนในไทย เทรดตาม gap เปิดตลาด | *พักอยู่* | **0฿** |
| **D · DW SET50** | DW SET50 ที่จดทะเบียนในไทย **ทุกผู้ออก** | เดย์เทรด ปิดก่อน 15:45 | 500฿ |
| **E · หุ้นไทยเดย์เทรด** | หุ้น SET สภาพคล่องสูง ที่วันนี้มีของจริงเกิดขึ้น | เดย์เทรด ปิดก่อน 15:45 | 1,000฿ |

ตอนนี้ **2,000฿ จาก 3,000฿ อยู่ในก้อนที่ปิดในวัน** (A + D + E) เหลือ 1,000฿
เป็นก้อนสวิงตัวเดียว — เบรกเกอร์ยังจำกัด **2 ไม้/วัน** เท่าเดิม การมีก้อนเพิ่ม
จึงไม่ได้แปลว่าเทรดถี่ขึ้น แค่แปลว่า 2 ไม้ที่เลือกได้มีของให้เลือกมากขึ้น

**ก้อนไหนงบ 0฿ = พักไว้ ไม่ใช่ลบทิ้ง** — ไม่มีการสแกน ไม่มีการ์ดบนหน้าเว็บ
ไม่มีบรรทัดในเทอร์มินัล แต่บันทึกเก่ายังอยู่และ `--review` ยังให้คะแนนย้อนหลังได้
เปิดกลับมาคือใส่ตัวเลขใน `ALLOC` ตัวเดียว ไม่ต้องแก้โค้ด

ที่ C · DR พักอยู่เพราะทุน 3,000฿ ซื้อมันไม่ค่อยไหว — DR ขั้นต่ำ 100 หน่วยเท่ากัน
DR ราคา 12 บาทจึงเป็นไม้ละ 1,200฿ คือเกือบครึ่งพอร์ตในเดย์เทรดไม้เดียว
ถ้าจะเปิดกลับ ควรลด `DR_MAX_PRICE` ให้พอดีกับงบที่ให้ไปพร้อมกัน

**A กับ D คือเครื่องเดียวกัน คนละดัชนี** — เกณฑ์คัด DW (spread, theta, BE,
เป้าต้องคุ้มค่าเข้าออก) เป็นความจริงของ DW ไม่ใช่ของฮั่งเส็ง โค้ดจึงมีชุดเดียว
แล้วอ่านว่า "ซีรีส์นี้เอาราคาจากไหน" จากตาราง `DW_SERIES` ใน config

| | A · DW HSI | D · DW SET50 |
| :-- | :-- | :-- |
| ดัชนี (TradingView) | `HSI:HSI` (ตลาดโลก) | `SET:SET50` (ตลาดไทย) |
| ตาราง DW (thaidw) | `underlying=HSI` | `underlying=S50` |
| ผู้ออกที่รับ | 18, 28 เท่านั้น | ทุกผู้ออก |
| เวลาทำการที่ยึด | HKEX | SET |
| futures ที่ DW เกาะจริง | HSIc1 | S50 สัญญาใกล้ |

ที่ SET50 รับทุกผู้ออกเพราะไม่มีเจ้าไหนครองตลาดแบบ 18/28 ฝั่งฮั่งเส็ง —
ปล่อยให้ด่าน spread เป็นคนคัดแทนการล็อกรายชื่อไว้ล่วงหน้า
เพิ่มดัชนีตัวที่สามในอนาคตคือเพิ่ม 1 แถวใน `DW_SERIES` + 1 บรรทัดใน `ALLOC`
ไม่ต้องแตะโค้ด

**C กับ E ก็เครื่องเดียวกัน** — ทั้งคู่ถามคำถามเดียวกันว่า "ของที่วิ่งเช้านี้
ยังมีคนไล่ซื้ออยู่ไหม และสิ่งที่มันเอื้อมถึงใหญ่กว่า 1 ช่องราคา + คอมพอหรือเปล่า"
ต่างกันแค่จักรวาลและความเข้มของด่าน (`INTRADAY_SERIES` ใน config)

| | C · DR | E · หุ้นไทยเดย์เทรด |
| :-- | :-- | :-- |
| จักรวาล | `type=dr` (กรอง NVDR ออก) | `type=stock` |
| มูลค่าซื้อขายขั้นต่ำ | 5 ลบ. | **100 ลบ.** |
| 1 ช่องราคาสูงสุด | 1.5% | **0.8%** |
| gap สูงสุด | 9% | **6%** |
| RVOL ขั้นต่ำ | ไม่มี | **1.5 เท่า** |

ก้อน E เข้มกว่าทุกด่านที่เกี่ยวกับเงิน เพราะ DR ซื้อตาม gap ที่เกิดไปแล้วเมื่อคืน
ส่วนหุ้นไทยซื้อตอนที่การเคลื่อนไหวยังก่อตัวอยู่ — จ่าย 1.5% ต่อช่องเพื่อลุ้นแบบนั้น
คือไม้ที่แพ้ตั้งแต่ยังไม่เริ่ม

**เพดานราคาคิดจากเงิน ไม่ใช่จาก config** — board lot คือ 100 หน่วย งบ 1,000฿
จึงซื้อหุ้นได้ไม่เกิน **10฿/หุ้น** สคริปต์เลยตัดที่เพดานนั้นตั้งแต่ตอนยิงฟีด
แล้วบอกไว้บนหัวกรอบ แทนที่จะดึงมา 300 ตัวเพื่อมาเขียนว่า "งบไม่พอ" ทีละตัว

แก้งบและเกณฑ์ทั้งหมดได้ที่ `trader/config.py`

## ⚠️ อ่านก่อนใช้ — 2 เรื่องที่สำคัญกว่าตัวสัญญาณ

**1. ค่าคอมขั้นต่ำจะกินพอร์ตขนาดนี้ทั้งเป็น**

โบรกหลายรายคิดค่าคอมขั้นต่ำ 50 บาท/วัน ถ้าคุณอยู่กับโบรกแบบนั้น
ไม้ละ 1,000 บาทจะเสียค่าธรรมเนียมไปกลับ 100 บาท = **10%** ซึ่งไม่มีสัญญาณ
เดย์เทรดไหนชนะต้นทุนขนาดนั้นได้

โบรกที่**ไม่มี**ขั้นต่ำ (ข้อมูลปี 2026): SBITO, LIB, Z, KS, BLS, FSS, GLOBLEX,
KINGSFORD, YUANTA, KKPS, CGSI, DAOLSEC, KTX

ถ้าย้ายโบรกหรือได้เรตอื่น แก้ `COMM_RATE` / `MIN_COMM` ใน `config.py`
แล้วตัวเลขต้นทุนทุกจุดจะอัปเดตตาม

**2. รันแล้วไปทำงาน = stop loss ไม่ทำงานเอง**

สคริปต์คำนวณจุดตัดขาดทุนให้ แต่ไม่มีใครกดขายให้คุณ วิธีใช้ที่ปลอดภัยคือ
**วาง limit sell ที่ราคา TP ทันทีหลังซื้อ** แล้วกำหนดขนาดไม้เท่ากับเงินที่
ยอมเสียได้ทั้งก้อน — บรรทัด `เสี่ยง …฿` ในผลลัพธ์คือตัวเลขนั้น

## ความเสี่ยง — ส่วนที่สำคัญกว่าตัวสัญญาณ

พอร์ตขนาดนี้ไม่ได้ตายเพราะไม้ที่แพ้ แต่ตายเพราะไม้ที่สามที่เข้าไปเอาคืน
เครื่องมือนี้จึงบังคับกฎ 3 ข้อให้เอง แก้ตัวเลขได้ที่ `trader/config.py`

| กฎ | ค่าเริ่มต้น | ทำไม |
| :-- | --: | :-- |
| `RISK_PER_TRADE` | 1.5% = **45฿/ไม้** | ขนาดไม้คิดจากระยะ SL ไม่ใช่จากงบ |
| `MAX_DAILY_LOSS` | 4% = **120฿/วัน** | ชนเมื่อไหร่ สคริปต์ไม่ยอมสแกนตลาดให้ดูอีก |
| `MAX_DAILY_TRADES` | **2 ไม้/วัน** | จ่ายค่าธรรมเนียมวันละ 2 รอบก็พอแล้ว |

**ขนาดไม้คิดจากระยะ SL ไม่ใช่จากงบ** — เดิมโค้ดถามว่า "งบ 1,000฿ ซื้อได้กี่ lot"
ซึ่งทำให้ทุกไม้เป็นการเดิมพันคนละขนาด DW ที่ SL ห่าง 40% เสี่ยง 400฿ = 13%
ของพอร์ตในไม้เดียว ส่วนตัวที่ SL ห่าง 10% เสี่ยงแค่ 100฿ ทั้งที่จ่ายเงินเท่ากัน

ตอนนี้มันถามกลับด้านว่า "ยอมผิดได้ 45฿ ซื้อได้กี่ lot" DW ตัวเดิม ask 0.48
SL 0.42 → **7 lot = 336฿** แทนที่จะเป็น 20 lot = 960฿ ไม้เท่าเดิม เสี่ยงราว 1/3
และแพ้ติดกัน 30 ครั้งพอร์ตยังเหลือสองในสาม

`ALLOC` จึงเปลี่ยนบทบาทจาก "เป้าที่ต้องใช้ให้หมด" เป็น **"เพดานห้ามเกิน"**
ผลลัพธ์บอกด้วยว่าขนาดไม้ถูกจำกัดด้วยอะไร — `งบ` หรือ `ความเสี่ยง`

**มันรู้ว่าคุณถืออะไรอยู่** — ก้อน B ถือ 5 วัน แปลว่าวันที่ 2 เงินยังจมอยู่
เมื่อก่อนสคริปต์ไม่รู้เรื่องนี้เลยและแนะนำหุ้นใหม่เต็มงบซ้ำอีกรอบ = นับเงินก้อนเดียว
สองครั้ง ตอนนี้มันหักของที่ถืออยู่ออกก่อนแล้วค่อยคิดขนาดไม้ และ**ไม่แนะนำตัวที่
ถืออยู่แล้ว หรือตัวที่เพิ่งโดน SL ไปในวันเดียวกัน**

**เบรกเกอร์นับเฉพาะไม้ที่ซื้อจริง** — คำแนะนำถูกบันทึกเป็น `SIGNAL` ซึ่งรันกี่รอบ
ก็ไม่นับ ต้อง `--took` ถึงจะกลายเป็น `ENTER` ที่เบรกเกอร์นับ ถ้าไม่ยืนยัน
เบรกเกอร์ก็ทำงานไม่ได้ — เป็นการแลกความขี้เกียจ 5 วินาทีกับกฎที่บังคับตัวเองได้จริง

## เทรดน้อยลง แต่ไม้ที่เข้าคุ้มค่าธรรมเนียม

ต้นทุนจ่ายต่อไม้ การเทรดบ่อยจึงเป็นกลยุทธ์ในตัวมันเอง — และเป็นกลยุทธ์ที่แพ้
DW spread 6% บนไม้ 1,000฿ คือ 60฿ ต่อเที่ยว เทรดทุกวัน 20 วันทำการ =
**1,200฿/เดือน = 40% ของพอร์ตทั้งก้อน** ก่อนจะรู้ด้วยซ้ำว่าทายถูกหรือผิด

จึงมี 3 ด่านที่ทำให้เข้าน้อยลงแต่แม่นขึ้น

**1. `DW_SIGNAL_ENTER` ขึ้นจาก 45 เป็น 60** — จากเทรดเกือบทุกวันเหลือสัปดาห์ละ 1–2 ครั้ง

**2. EMA 15m ต้องเรียงตรงทาง** (`DW_REQUIRE_ALIGN`) — ค่านี้ถูกคำนวณอยู่แล้วตั้งแต่ต้น
แต่เอาไปพิมพ์เป็นตัวหนังสือสีจางเฉย ๆ ไม่เคยเป็นเกณฑ์ตัด ใช้เป็นด่านไม่ต้องยิงข้อมูล
เพิ่มสักครั้ง และมันตัดเคสที่คะแนนพุ่งตอนราคายังพันกับเส้นค่าเฉลี่ยตัวเอง —
ไม้ที่จ่าย spread จริงแต่ move ไม่เคยมา

**3. `MIN_EDGE_MULTIPLE = 3.0`** — เป้าต้องได้อย่างน้อย 3 เท่าของค่าเข้าออกไปกลับ
ต่างจาก `DW_MAX_SPREAD` ที่เป็นเกณฑ์ลอย ๆ (8% ของอะไร?) ด่านนี้เทียบต้นทุนกับ
สิ่งที่ไม้นั้นกำลังเอื้อมถึงจริง

| ก้อน | นับต้นทุนจากอะไร |
| :-- | :-- |
| A · DW | spread + คอมไปกลับ |
| B · หุ้น | คอมอย่างเดียว — ถือหลายวัน ช่องราคาเป็นเศษเงิน |
| C · DR | คอม + 1 ช่องราคา — เข้าออกในวันเดียว กริดคือต้นทุนจริง |

## สถานะที่ถืออยู่

ทุกครั้งที่รัน จะมีกรอบบอกว่าตอนนี้ถืออะไร ราคาเท่าไหร่แล้ว กำไรขาดทุนเท่าไหร่
ถือมากี่วัน และ**เตือนเมื่อหลุด SL / ถึง TP / ถือเกินกำหนด / DW ค้างข้ามคืน**

ราคาที่ใช้คือ**ราคาที่ขายออกได้จริง** — DW ตีที่ bid ไม่ใช่ราคาซื้อขายล่าสุด
เพราะ DW ที่เสนอ 0.45/0.48 นั้นราคาล่าสุดไม่ใช่ราคาที่คุณออกได้
และการแกล้งทำเป็นว่าใช่ คือวิธีที่สถานะดูดีจนถึงวินาทีที่กดขาย

## ก้อน DW (A และ D) ทำงานอย่างไร

แยกเป็น 2 คำถามที่ไม่เกี่ยวกัน และตอบตามลำดับ

**1. ดัชนีไปทางไหน** — รวมคะแนนจาก 5m / 15m / 60m ถ่วงน้ำหนัก 0.25 / 0.45 / 0.30
โดย 15m ได้น้ำหนักมากที่สุดเพราะช้าพอจะรอด spread ตอนเปิด และเร็วพอจะปิดในวัน
ถ้า `|คะแนน| < 60` → ไม่เข้า และต่อให้ถึง 60 แล้ว EMA 15m ยังต้องเรียงตรงทางด้วย

**2. แล้วซื้อตัวไหน** — คัด DW ทุกตัวในซีรีส์นั้น (ฮั่งเส็ง 31 ตัว)
ด้วยเกณฑ์ที่ทำให้ "เทรดไม่ได้จริง"

| ตัด | เพราะ |
| :-- | :-- |
| ไม่มี bid | ซื้อได้แต่ขายไม่ออก |
| อ่านวันหมดอายุไม่ออก | ของที่เสีย theta ทุกวัน ไม่เดาวันหมดอายุ |
| เหลือ < 10 วัน | theta cliff |
| spread > 8% | ค่าเข้าออกกินกำไรหมด |
| เป้า < 3 เท่าของต้นทุน | ถูกแต่ไม่คุ้ม — จ่าย spread ไปเอาเศษ |
| 1 lot เสี่ยงเกิน 45฿ | ไม้เดียวกินโควตาความเสี่ยงทั้งวัน |
| งบไม่พอ 1 lot | DW ซื้อขั้นต่ำ 100 หน่วย |

ที่เหลือเรียงด้วย `gearing / (1 + spread/2) − theta×1.5 − ส่วนที่ OTM เกิน 5%`

**ตัวเลขที่ต้องดูให้เป็น: `BE จุด`** = ดัชนีต้องวิ่งกี่จุดถึงจะเสมอตัว
เพราะซื้อที่ ask แล้วขายที่ bid แปลว่าจ่าย spread ไปตั้งแต่วินาทีแรก
DW ที่ราคา 0.03/0.04 คือจ่าย 33% ทันที — ทายทางถูกก็ยังขาดทุน

**ทำไมต้องมีผู้ออก 28 ด้วย ไม่ใช่แค่ 18** — ฝั่ง 18 มี DW แค่ 6 ตัว
บางวันไม่มีตัวไหนผ่านเกณฑ์เลยแม้แต่ตัวเดียว โดยเฉพาะฝั่ง PUT
การเปิดให้เห็นทั้ง 31 ตัวทำให้ยังมีของให้เลือกเมื่อสัญญาณมา

**หมายเหตุ underlying** — DW ฮั่งเส็งในไทยอ้างอิง **HSI Futures (HSIc1)**
ไม่ใช่ spot index ทั้งสองห่างกันหลายสิบจุดและ futures เทรดนอกเวลา cash market
ผลลัพธ์จึงแสดงทั้งคู่ ฝั่ง SET50 ก็เหมือนกัน DW เกาะ **S50 futures** ไม่ใช่
ดัชนี SET50 เอง ถ้าฟีดไม่มีราคา futures ของซีรีส์นั้น บรรทัดนั้นจะหายไปเฉย ๆ
ไม่ทำให้ทั้งก้อนล่ม

**ตัวเลขของ SET50 คนละสเกลกับฮั่งเส็ง** — ดัชนีอยู่แถว 1,000 จุด ไม่ใช่ 25,000
`sensitivity` ต่อ 100 จุดจึงสูงกว่ามาก และ ATR 15m เป็นหลักหน่วยจุด เกณฑ์ทุกตัว
ในตารางข้างบนเป็น % หรืออิงจุดคุ้มทุนอยู่แล้ว จึงใช้ได้ทั้งสองซีรีส์โดยไม่ต้องตั้งค่าแยก

## เปิดดูบนมือถือ (deploy ขึ้น Vercel)

ทำครั้งเดียว จากนั้น `git push` ทุกครั้งจะ deploy ให้เองอัตโนมัติ

1. เข้า [vercel.com/new](https://vercel.com/new) → **Import Git Repository** → เลือก `dime_hsi`
2. กด **Deploy** (ไม่ต้องตั้งค่าอะไร — `vercel.json` กำหนดไว้ให้แล้ว)
3. ได้ URL แบบ `https://dime-hsi.vercel.app` เปิดจากมือถือได้เลย

ดูหน้าเว็บก่อน deploy ได้ด้วย

```bash
python3 run.py --html brief.html && xdg-open brief.html
```

**ทำไมต้องเป็น serverless ไม่ใช่หน้า static** — ทั้ง TradingView และ thaidw
ไม่ส่ง CORS header เบราว์เซอร์เรียกตรงจึงโดนบล็อก ต้องให้ฝั่งเซิร์ฟเวอร์เรียกแทน
แลกมาด้วยข้อดีคือหน้าเว็บคำนวณสดทุกครั้งที่เปิด ไม่ต้องรอ cron

## บันทึกการเทรด

ทุกคำแนะนำถูกเขียนต่อท้าย `journal.jsonl` (ไม่ขึ้น git) เพื่อให้ย้อนวัดได้จริง
ว่าสัญญาณทำเงินหรือเปล่า แทนการเชื่อความทรงจำ ปิดด้วย `--no-journal`

มี 3 ชนิด: `SIGNAL` คือสิ่งที่สคริปต์แนะนำ `ENTER` คือไม้ที่คุณยืนยันด้วย `--took`
ว่าซื้อจริง และ `EXIT` คือตอนปิดพร้อมกำไร/ขาดทุนที่หักค่าธรรมเนียมแล้ว
เบรกเกอร์กับการคิดเงินว่างใช้แค่ `ENTER`/`EXIT` เท่านั้น

**`--review` คืออีกครึ่งที่หายไป** — เดิม journal เขียนอย่างเดียวไม่เคยอ่านกลับ
แปลว่า `DW_SIGNAL_ENTER`, `CHEAP_MIN_RR` และน้ำหนัก timeframe ทั้งหมดเป็นการเดา
ที่ตรวจสอบไม่ได้ตลอดกาล

ตัวเลขที่ตัดสินว่าก้อนไหนอยู่ต่อคือ **กำไรเฉลี่ยต่อไม้หลังหักต้นทุน** ไม่ใช่อัตราชนะ
ก้อนที่ชนะ 60% ยังขาดทุนได้ ถ้า 40% ที่แพ้ใหญ่กว่า หรือถ้ามันจ่ายค่าเข้าออกบ่อยพอ
ต่ำกว่า 10 ไม้มันจะบอกว่ายังสรุปไม่ได้ แทนที่จะจัดอันดับสัญญาณรบกวน

```
ก้อน         ไม้   ชนะ    %ชนะ     ได้เฉลี่ย    เสียเฉลี่ย  ค่าธรรมเนียม       สุทธิ฿     ต่อไม้฿
A · DW      14     5     36%         95        -60         112        -65        -5
B · หุ้น      11     7     64%        120        -70          88       +560       +51
C · DR       2     1     50%         40        -25          16        +15        +8

A · DW    เสีย -5฿/ไม้ — ตัดก้อนนี้ทิ้ง เอาทุนไปก้อนที่ได้
B · หุ้น    ได้ +51฿/ไม้ — เก็บก้อนนี้ไว้
C · DR    ยังน้อยเกินสรุป (2/10 ไม้)
```

พอร์ต 3,000฿ รัน 3 กลยุทธ์พร้อมกันน่าจะกระจายจนไม่เหลือน้ำหนัก คำถามคือควรเหลือ
ก้อนไหน และนี่คือวิธีตอบด้วยหลักฐานแทนความรู้สึก — ตอนนี้ตอบไปแล้วหนึ่งก้อน
คือ C · DR ที่พักไว้ (`ALLOC['dr'] = 0`) ตัวเลขเก่าของมันยังอยู่ในตารางนี้

ตั้ง `DIME_JOURNAL=/path/to/file.jsonl` เพื่อชี้ไปไฟล์อื่น (ใช้ตอนทดลอง
จะได้ไม่ปนกับบันทึกจริง)

---

## โครงสร้าง

```
run.py                    CLI + การแสดงผล  (--html สร้างหน้าเว็บ)
selftest.py               ตรวจว่าทุกบรรทัดพอดีกรอบ (รันหลังแก้คอลัมน์)
test_offline.py           ตรวจ sizing / ด่านคัด / เบรกเกอร์ / review — ไม่ใช้เน็ต
vercel.json               ตั้งค่า deploy
api/index.py              serverless entry point
web/
├── report.py             เก็บข้อมูลทุกก้อนพร้อมกัน (ใช้ร่วมกับ terminal)
├── page.py               ประกอบหน้า HTML
└── html.py               CSS + ชิ้นส่วนกราฟ (เกจ, ladder, RR bar)
trader/
├── config.py             งบ เกณฑ์ ความเสี่ยง เวลา — แก้ที่นี่ที่เดียว
├── sizing.py             ขนาดไม้จากระยะ SL, ค่าธรรมเนียม, spread, ช่องราคา
├── risk.py               โควตาความเสี่ยงรายวัน + สถานะที่ถืออยู่
├── marks.py              ตีราคาสถานะที่ถืออยู่ตามราคาที่ขายออกได้
├── review.py             อ่าน journal กลับ — กำไรต่อไม้รายก้อน
├── journal.py            บันทึก jsonl (SIGNAL / ENTER / EXIT)
├── cache.py              ประวัติราคาสำหรับ sparkline
├── graph.py              เกจ แถบ ladder กรอบ — คำนวณความกว้างแบบรู้จักสระไทย
├── ui.py                 สีและการจัดรูปแบบ
├── session.py            ตลาดเปิดอยู่หรือเปล่า — กันหน้าจอโกหกว่าราคาสด
├── feeds/
│   ├── net.py            retry + เส้นตาย ใช้ร่วมกันทั้งสองฟีด
│   ├── tv.py             TradingView scanner
│   └── thaidw.py         ตาราง DW + futures (ต่อ underlying)
└── buckets/
    ├── dw.py             ก้อน A และ D — เครื่อง DW ตัวเดียว ใช้ได้ทุกดัชนี
    ├── cheap.py          ก้อน B
    └── intraday.py       ก้อน C และ E — เครื่องเดย์เทรดตัวเดียว ใช้ได้ทั้ง DR และหุ้น
```
